# Pipeline reliability audit — 2026-10-25

Audited merged dev `6911b2c` and applied focused fixes on
`fix/pipeline-reliability-audit`.

## Confirmed defects corrected

- Empty/failed photo remarks could call Gemini or TTS again on every poll. An
  attempt is now recorded before provider calls and retained for the job lifetime,
  including empty, rejected or failed-voice outcomes. The final answer still wins.
- Corrupt saved camera cursors could keep polling invalid parameters. Cursor
  shape/date/ID are now validated before use, with existing fresh-session fallback.
- Postgres Results assumed the first requested target was the found target. A
  real AirPods/phone record had only phone detected. The query now selects an
  observed requested target, and the displayed target follows the actual match.

## Deployment and remaining limits

- The desktop user worker is active with zero automatic restarts; its config and
  production data were preserved.
- Per the user's instruction, web DB/S3 configuration is unchanged. Web currently
  uses S3 fallback because its local Postgres endpoint is unavailable. Its UI
  history is consequently bounded by retained/recent S3 results. Desktop durable
  memory still reads the working Postgres database directly.
- Pi SSH at `100.127.34.75` timed out twice. Current physical button, microphone,
  camera and Pi service state could not be verified; software tests are not a
  substitute for that hardware acceptance.
- Existing storage references include 57 photos: 23 raw/annotated pairs are
  present and 34 pairs are missing. Missing objects predate these fixes. Stored
  locations remain, but missing historical images cannot be displayed. No rows or
  objects were deleted, restored or reprocessed by this audit.
- Device discovery still assumes aligned browser/Pi clocks at a fresh session.
  A delayed upload with an older creation timestamp, or a clock ahead of the Pi,
  can be missed by the current no-replay cursor. A server-arrival cursor would
  require a separate discovery-contract change; this audit preserves that policy.
- Matching uses categories/descriptions and exact configured aliases, not
  individual-object identity. Multiple instances can be detected, but the current
  primary answer/photo mark selects one matching instance.
- No new live paid-provider or complete hardware voice loop was claimed.
