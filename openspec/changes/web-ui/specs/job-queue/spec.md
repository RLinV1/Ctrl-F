# Spec Delta

## Purpose

Hands each voice request from the browser to the Raspberry Pi and back: the web stores the request's audio, queues a job, lets the Pi claim it with outbound calls only, and reports the job's outcome to the browser.

## ADDED Requirements

### Requirement: Issue an audio upload slot
`POST /api/uploads` SHALL return a new private storage key for one audio clip and a short-lived URL the browser can upload that clip to directly. The key SHALL be generated by the server; the browser SHALL NOT choose it.

#### Scenario: Upload slot issued
- **WHEN** a signed-in browser calls `POST /api/uploads`
- **THEN** the response is `201` with an `audioKey` under the audio prefix and an `uploadUrl` that expires within 10 minutes

### Requirement: Create a job only for stored audio
`POST /api/jobs` with an `audioKey` SHALL create a job with status `pending` only when an object exists at that key. Otherwise it SHALL reject the request and create no job. Jobs created by the website carry the source `web`.

#### Scenario: Job created after upload
- **WHEN** the browser has uploaded a clip to its slot and calls `POST /api/jobs` with that `audioKey`
- **THEN** the response is `201` with the job `id` and status `pending`

#### Scenario: Audio missing
- **WHEN** `POST /api/jobs` names an `audioKey` with no stored object
- **THEN** the response is `400` and no job row is created

### Requirement: Create a job from typed text
`POST /api/jobs` with `text` SHALL create a `pending` job whose transcript is that text, trimmed, with no audio, so speech-to-text is skipped. Empty text or text over 300 characters SHALL be rejected with `400`.

#### Scenario: Typed question
- **WHEN** the browser calls `POST /api/jobs` with `{ "text": "where are my glasses" }`
- **THEN** the response is `201` with a `pending` job, and once done the job's transcript is "where are my glasses"

#### Scenario: Empty or too long
- **WHEN** the text is blank or longer than 300 characters
- **THEN** the response is `400` and no job is created

### Requirement: Camera button questions
`POST /api/device/jobs` SHALL accept a recording from the camera's own mic as a raw `audio/*` body, authenticated only by the Pi's bearer token, store it privately, and create a `pending` job with source `device`. The Pi then claims it through `GET /api/jobs/next` like any job.

#### Scenario: Button pressed
- **WHEN** the Pi posts a 3-second webm recording with a valid token
- **THEN** the response is `201` with the job `id`, the job's source is `device`, and the next claim returns it

#### Scenario: Rejected upload
- **WHEN** the token is wrong, the content type is not audio, or the body is empty
- **THEN** the response is `401`, `400` or `400` respectively and no job is created

### Requirement: Find the newest job from a source
`GET /api/jobs/latest?source=device&since=<time>` SHALL return the `id` of the newest job from that source created after `since`, or `204` when there is none, so the page can show camera-button questions.

#### Scenario: A press since the page started listening
- **WHEN** a device job was created after `since`
- **THEN** the response is `200` with its `id`

#### Scenario: Nothing new
- **WHEN** no device job was created after `since`
- **THEN** the response is `204`

### Requirement: Pi claims the oldest pending job
`GET /api/jobs/next` SHALL require the Pi's bearer token, atomically move the oldest `pending` job to `claimed` with a claim time, and return its `id`. Two concurrent calls SHALL NOT claim the same job.

#### Scenario: Job available
- **WHEN** the Pi calls with a valid token and two jobs are pending
- **THEN** the response is `200` with the older job's `id`, and that job is now `claimed`

#### Scenario: Nothing to do
- **WHEN** the Pi calls with a valid token and no job is pending
- **THEN** the response is `204` with no body

#### Scenario: Concurrent claims
- **WHEN** two calls arrive at the same time and one job is pending
- **THEN** exactly one call receives that job and the other receives `204`

#### Scenario: Bad token
- **WHEN** the call has no token or a wrong token
- **THEN** the response is `401` and no job changes status

### Requirement: Report a job's outcome
`GET /api/jobs/:id` SHALL return the job's status and, once `done`, the transcript, target item, found flag, reply text, a signed reply-audio URL when audio exists, and the matched snapshot as a signed URL with the matched box. A `failed` job SHALL include its error.

#### Scenario: Done and found
- **WHEN** the desktop has finished a job that found the target
- **THEN** the response has status `done`, `found: true`, the reply text, a signed snapshot URL, and the matched box as `{x, y, w, h}` fractions

#### Scenario: Done and not found
- **WHEN** the desktop has finished a job whose target was not visible
- **THEN** the response has status `done`, `found: false`, the reply text, and the item's last sighting (time, signed snapshot URL, box) when one exists

#### Scenario: Reply without audio
- **WHEN** the job is `done` but text-to-speech failed
- **THEN** the response has the reply text and no reply-audio URL

#### Scenario: Reply with word timings
- **WHEN** the job is `done` and the desktop stored word timings for the reply audio
- **THEN** the response includes the timings as a list of `{word, start, end}` in seconds, in reply order

#### Scenario: Unknown job
- **WHEN** the id does not exist
- **THEN** the response is `404`

### Requirement: Expose staleness without changing stored state
`GET /api/jobs/:id` SHALL report `stale: true` when a job has been `pending` for more than 20 seconds or `claimed` for more than 60 seconds, without changing the stored status.

#### Scenario: Pi never picks up
- **WHEN** a job has been `pending` for 25 seconds
- **THEN** the response has status `pending` and `stale: true`

### Requirement: Media is private
Every audio and snapshot URL returned by the job API SHALL be a signed URL that expires within 15 minutes. Storage keys SHALL NOT be usable without a signed URL.

#### Scenario: Signed snapshot
- **WHEN** a response includes a snapshot
- **THEN** its URL carries a signature and an expiry no more than 15 minutes ahead
